Critical & high-priority issues

The handful of things worth fixing before anything else — either because they break the app outright, mislead a reader about what study they're in, or carry legal/security weight.

Five studies contain content copied from a different study

Critical

Traced this to a clear pattern: new studies appear to have been built by cloning the JSON of a previous study, and the onboarding slides, "How to use this study" page, AI Tutor prompt, or leaders' notes weren't always fully rewritten afterward. Grepping the whole library for the leftover study titles confirms the scope precisely:

Exploring Deuteronomy — its onboarding slides, How To Use page, and AI Tutor prompt are entirely about "1 John for Today" (wrong book, wrong theme, wrong session count). Leaders' notes are correctly about Deuteronomy.

Exploring Isaiah — same leftover: How To Use and the AI Tutor prompt are both about "1 John for Today." Leaders' notes and onboarding slides are correctly Isaiah-specific.

Exploring Hebrews — was evidently cloned from Deuteronomy rather than the template directly: its AI Tutor prompt says "1 John for Today," its tags say ["old testament","hebrews"], and ten of its twelve leaders'-notes chapters (~166 KB) are genuine Deuteronomy 4–16 commentary, not Hebrews. See the next card — this file has a second, larger problem too.

Her Own Name (1) & (2) — both studies' entire leadersNotesData sections are copied from Grow in Christ (its "Growth Graph" diagram, its septic-tank illustration, the parable of the lost son) — nothing about pastors' wives, identity, or calling. Volume 2's copy even keeps Volume 1's seven-chapter numbering, though this study has six.

Bible translation credited doesn't match the text quoted

High

Three studies' metadata and copyright pages name one Bible translation — with that publisher's full copyright notice — while every actual passage quotes a different one:

What Rules My Heart — metadata and copyright page both say NIV (Biblica's copyright block, in full), but all 163 Bible passages are tagged NET and link to NET on Bible Gateway.

Worth fixing before wider release — crediting the wrong publisher for the actual text isn't just cosmetic.

The same API key is embedded in plain text across the library

High

Every study with an AI Tutor sets studyAiData.apiKey to what looks like a live, working credential (the app's own "obfuscated" format — its README already notes this scheme "deters casual inspection only — it is NOT secure storage"). It's the identical value in at least 15 of the studies checked, which reads as one shared key reused everywhere rather than a placeholder. Not reproduced here — worth a direct check with whoever owns the AI Tutor backend on whether this key is live, and if so whether it should move behind a server-side proxy rather than shipping inside every study file.

Present in most studies with an AI Tutor configured — not itemised per file below.

Patterns that recur almost everywhere

Three issues showed up in nearly every file checked. Rather than list each occurrence per study above, here's what they are and roughly how big each one is — worth a global pass rather than fixing file by file.

Wrong-direction curly quotes nearly every study

Scare-quoted words and phrases are set with the right single quotation mark (’) on both sides, instead of an opening ‘ paired with a closing ’. Counts run from a few dozen to several hundred per file — Find Rest for your Soul alone has 366 instances, Isaiah and Jonah both run into the hundreds. A smaller but sharper version shows up too: quotes that are fully backwards (’text‘ rather than ‘text’), which reads as broken punctuation rather than just a style choice.

“come ’from within’” ← should open with ‘ “’helpless,‘ ’ungodly,‘” ← fully backwards

Curly quotes used to delimit HTML attributes 10+ studies, 400+ instances

Wherever a passage or callout embeds a raw <a href=…>, <span style=…>, or <table>, the attribute value is sometimes delimited with a curly quote instead of a straight one. A curly quote isn't a valid HTML attribute delimiter, so the tag won't parse as intended — the link, the styling, or the whole table can break depending on the renderer. Isaiah (89 instances) and Jonah (118) are the worst affected; Who am I has a whole table built this way.

<a href=’https://www.biblegateway.com/…’> ← should be href="…"

Publisher domain: .co.uk or .org.uk? 4 studies checked

Knowing God through Jesus, Conversion, Find Rest for your Soul, and Grow in Christ all give the same publisher's URL two different ways in the same file — studyAboutData.publisher.url says beaconlight.co.uk, imageData.publisher.provenance says beaconlight.org.uk. Worth settling on the correct one and sweeping it everywhere at once, since it's clearly the same organisation info block copied study to study.
